# 图形化用例配置界面 · 术语表与控件说明

> 目的：统一「功能用例配置（Function 模块）」图形化界面中各组件的命名，便于后续准确、高效地沟通。
> 涉及源码目录：`frontend/src/components/graph/`、`frontend/src/types/functionGraph.ts`、`frontend/src/utils/functionGraph.ts`、`backend/services/function_graph.py`。

---

## 1. 总体架构

功能模块（Function）的用例编排包含两种画布模式：

| 模式 | 英文/代码术语 | 说明 |
|------|--------------|------|
| 自由画布模式 | Graph Canvas（`nodes` + `edges`） | 早期连线式编排，三泳道 + 组节点 + 连线 |
| 工况框模式 | CaseFrame（`frames`） | 新版用例编排，以「工况框」为容器，纵向排列 |

前端数据模型统一定义在 `types/functionGraph.ts`，与后端 Python 字典结构等价。

---

## 2. 面板与停靠布局

### 2.1 面板（Panel）

编辑器由若干可停靠「面板」组成，每个面板有唯一 `panelId`：

| panelId | 顶部按钮文案 | 面板标题（title） | 用途 |
|---------|-------------|------------------|------|
| `frames` | 工况 | 工况 | 工况列表，一个工况 = 一个用例模板 |
| `inject` | 故障注入 | 故障注入 | 故障注入 / 故障恢复卡片库（分类展示） |
| `sequence` | 序列 | 测试序列 | 测试序列卡片库 |
| `result` | 检查 | 结果判断 | 结果判断卡片库 |
| `editor` | （无按钮） | 编辑 | 中间编辑区：选中卡片时显示步骤编辑器，否则显示工况框画布 |
| `mapping` | （无按钮） | 对象映射表 | 变量名 ↔ 对象的映射管理 |
| `func` | 函数库 | 函数库 | CAPL 函数库（拖拽函数生成步骤） |
| `obj` | 对象浏览器 | 对象浏览器 | 浏览 DBC/DTC/A2L 对象，拖拽到步骤/参数 |

> ⚠️ 命名易混淆点：`sequence` 在顶部按钮叫「序列」，面板标题叫「测试序列」；`result` 在顶部按钮叫「检查」，面板标题叫「结果判断」。卡片类型层面统一用「测试序列 / 结果判断」。

### 2.2 停靠布局（Dock Layout）

- **布局树（LayoutNode）**：由两种节点组成的树结构
  - **分栏（Split）**：`dir = row`（左右分栏）/ `column`（上下分栏），通过 `ratios` 控制比例，可拖动分隔条调整。
  - **页签分组（Tab Group）**：多个面板共享同一区域，通过页签切换激活。
- **浮动面板（Floating Panel）**：从停靠树脱离、自由定位的面板。
- **五向放置区（Five-zone Drop Overlay）**：拖拽面板停靠时出现的上 / 下 / 左 / 右 / 中 五个放置热区。

## 3. 画布模式

### 3.1 自由画布（Graph Canvas）

- **泳道（Lane）**：三列纵向分区，从左到右依次为：
  - 故障注入（`inject`）
  - 测试序列（`sequence`）
  - 结果判断（`result`）

### 3.2 工况框（CaseFrame）

「工况框」是新版用例编排的核心容器，一个工况框纵向排列，宽度填满容器。框内分为三个列区（Zone）：

| 列区 | 代码字段 | 排列方向 |
|------|---------|---------|
| 故障注入列 | `injects` | 从上往下 |
| 故障恢复列 | `recovers` | 从下往上（与注入同列，反向堆叠） |
| 测试序列列 | `sequenceId` | 单个序列卡片，含多个步骤 |
| 结果判断列 | `results` | 从上往下 |

## 4. 卡片、节点、端口、连线

### 4.1 卡片（Card）

最小可复用单元，`type` 决定所属泳道：

- 故障注入（`inject`）
- 测试序列（`sequence`）
- 结果判断（`result`）

关键字段：

- **步骤列表（steps）**：卡片内部最小执行单元集合。
- **组合卡片（Composite Card）**：`steps.length >= 1` 的可复用步骤集合。
- **卡片引用（refId）**：指向卡片库中卡片的 id，卡片库更新后由编辑器同步覆盖内容。
- **故障角色（InjectRole）**：仅 `type = inject` 的卡片使用，区分「故障注入（`inject`）/ 故障恢复（`recover`）」，两者同存于 `inject` 桶。
- **局部变量（locals）**：卡片定义的用例局部变量。

### 4.2 节点（GroupNode）

自由画布模式中的节点，一个节点内含 N 张卡片：

- **扇出（Fanout）**：
  - `single`：1 个聚合口，合并所有卡片步骤。
  - `multi`：每张卡片 1 个口。

### 4.3 端口（Port）

节点/卡片的对外连接点：

- **输入口（port-in）**：连接来自上游的连线。
- **输出口（port-out）**：连接去往下游的连线。

工况框内端口 key 约定（见 `FrameEdge` 注释）：

| 端口类型 | key 格式 | 说明 |
|---------|---------|------|
| 故障注入 | `inj:<nodeId>` | 仅右口（输出） |
| 故障恢复 | `rec:<nodeId>` | 仅右口（输出） |
| 结果判断 | `res:<nodeId>` | 仅左口（输入） |
| 序列步骤 | `seq:<seqId>:<stepIdx>` | 左口输入 + 右口输出 |

### 4.4 连线（Edge / FrameEdge）

- **自由画布连线（Edge）**：`from` / `to`，各含 `nodeId` 与 `portIndex`。
- **工况框连线（FrameEdge）**：
  - **序号（seq）**：注入 → 序列连线的序号（1、2、3…），注入与恢复共用同一序号进行配对。
  - **配对序号（pair）**：序列 → 结果连线的配对序号（从小到大，空数组 = 对应全部注入）。

## 5. 步骤与循环

### 5.1 步骤（CardStep）

卡片内部的最小执行单元，`kind` 决定渲染方式：

| kind | 中文名 | 说明 |
|------|--------|------|
| `call` | 函数调用 | 调用 CAPL 函数 |
| `set` | 设置 | 设置信号/变量值 |
| `check` | 检查 | 信号值判断（生成 `SignalCheck`） |
| `reset` | 恢复 | 恢复单个对象初始值 |
| `reset_all` | 恢复全部 | 自动展开为该用例所有 set 对象的恢复语句 |
| `wait` | 等待 | 等待时间 |
| `loop_start` | 循环开始 | 循环体起点 |
| `loop_end` | 循环结束 | 循环体终点 |
| `raw` | 原始行 | 原始 CAPL 行 |
| `card` | 卡片引用 | 步骤级引用另一张卡片，生成时递归展开其 steps |

> 「设置 / 检查 / 恢复」在界面上渲染为「对象卡片块」，下方为多行对象参数（一行 = 一个对象）。

### 5.2 循环体（Loop）

`loop_start` / `loop_end` 成对出现。`loopMode` 决定循环类型：

| loopMode | 中文名 | 参数 | 生成代码 |
|----------|--------|------|---------|
| `for` | 次数可控 | 初值（init）/ 次数（count）/ 步增（step） | `for (loopIdxN = init; loopIdxN < count; loopIdxN += step) {` |
| `while` | 条件退出 | 退出条件（condition） | `while (1) { if (condition) break; …` |

- 多个循环体按出现顺序自动分配循环变量 `loopIdx1`、`loopIdx2`…，并在 testcase 开头统一声明（符合 CAPL「变量必须在函数开头声明」规范）。

## 6. 映射表与局部变量

### 6.1 映射表（ObjectMapping）

变量名（别名）↔ 真实对象名的对照表，生成时按别名解析为真实对象名。分五类：

| 分类 | 代码字段 | 中文名 |
|------|---------|--------|
| signal | `signals` | 信号 |
| dtc | `dtcs` | DTC |
| message | `messages` | 报文 |
| envvar | `envvars` | 环境变量 |
| a2l | `a2l` | A2L |

每个条目（MappingEntry）：`alias`（变量名）、`kind`（分类）、`name`（真实对象名）、`value`（可选值）。

### 6.2 局部变量（LocalVar）

用例局部变量，生成时在 testcase 顶部声明：`name`（变量名）、`type`（类型）、`value`（初始值，可选）。

---

## 7. 展开与用例

- **展开（Expand）**：把图（自由画布）或工况框展开为有序的用例序列。
  - 自由画布：按拓扑展开，同链串联、分叉并联，用例数 = 注入起点到死端的全部路径数。
  - 工况框：`expandFramePaths`，序列为主干，注入插在连线所接步骤之前，结果接在所接步骤之后。
- **用例（Test Case / Case）**：展开后的单个用例，含 `case_id` 与 `steps`。
- **用例链预览（Chain）**：端口 label 串联的用例链路展示。

## 8. 交互与快捷键

| 操作 | 说明 |
|------|------|
| 拖拽卡片到工况 | 在工况框对应列区创建节点 |
| Ctrl + 拖拽复制 | 卡片/工况按住 Ctrl 拖拽到列表区可复制，名称后追加序号（2、3、4…）；故障注入卡片可复制到「故障恢复」分区 |
| 拖拽排序 | 步骤/卡片上下拖动排序，Ctrl 拖拽复制 |
| 拖拽函数/对象 | 拖入步骤列表自动生成步骤或填充参数 |
| 双击 | 双击节点/卡片进入编辑 |
| Ctrl + C / Ctrl + V | 复制 / 粘贴选中的工况、卡片或步骤 |
| Ctrl + S | 保存（优先保存正在编辑的卡片） |
