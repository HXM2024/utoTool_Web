# CAPL 编码规范（测试工程）

> 适用范围：本工程 CANoe / CAPL 测试代码（`.can` / `.cin`）。目标：**用例只描述「做什么、期望什么」，机制全部下沉到函数层**；代码可读、可复用、可回归，出问题能快速定位。
>
> 版本：V1.0

---

## 一、分层与职责

| 层 | 放什么 | 禁止 |
|---|---|---|
| **用例层**（`testcase`） | 一行调用 + 期望判定 | 硬编码报文 ID、裸 `output()`、裸 `putValue` 注故障、散落的魔法等待值、直接调 DLL/DAQ 命令 |
| **函数层**（模板/库函数） | 设值、等待、采集、换算、比较、清 DTC、复位；如 `_SignalCheck`、`_Signalfactor`、`SignalWaitCheck`、`_testnullDTC`、`Req14` | 直接操作总线与硬件细节以外的东西 |
| **底层**（总线 / DLL / DAQ） | `output()`、`putValue`、`testDisableMsg`、DLL 采集命令 | 被用例层直接调用 |

**一句话判据**：用例里出现「报文 ID、字节、DLL、协议、魔法数」就是越界。

## 二、命名与文件约定

- **文件头**：保留 `/*@!Encoding:65001*/`（或工程统一的 936）编码指令，位置和写法不要动；没有的不要擅自加。
- **故障注入变量**：统一 `EV_` 前缀，如 `EV_CRC_xxx`、`EV_Counter_xxx`。
- **阻塞式标签**：`includes {}` / `variables {}` / 函数 / 事件处理程序的骨架一定要保留，即使为空。
- **函数命名**：动词或动宾短语，能一眼看出做什么，如 `SignalWaitCheck`、`_InjectFault`、`ccpReadValue`；内部辅助前缀 `_`。
- **缩进**：统一 2 或 4 空格，同一文件内一致，不用 Tab 混排。

## 三、语法纪律（CAPL ≠ C，最容易踩）

### 1. 局部变量：默认 static，声明必须在块首

```capl
void f()
{
    int i, n;          // ① 声明全部放块首
    i = 0;             // ② 之后才是语句
    n = getCount();
    for (i = 0; i < n; i++)
    {
        int t;         // ③ 这是 for 体这个块的块首，允许
        t = i * 2;
    }
}
```

- 函数局部变量**默认 static，跨调用保留值**。需要每次干净的，要么用 `stack`，要么**在函数开头显式赋值清零**。
- **禁止**在语句之后声明变量；**禁止**在 `for (...)` 头里声明变量。
- **禁止**在声明里做「计算式初始化」后依赖它每次重置——它只在加载时执行一次。
- 需要声明 + 初始化，只有两种场合安全：`variables {}` 里的全局量，以及字面量初始化（`char s[5]="test";`、花括号数组）。

### 2. 没有的东西，别写

| 不许写 | 替代 |
|---|---|
| `unsigned` | `byte`(1) / `word`(2) / `dword`(4) / `qword`(8) |
| `static` 修饰局部变量 | 默认就是 static；要非 static 用 `stack` |
| 指针、`&x`、`*p`、`s + i`、`&s[i]` | 无指针；`&` 只用于「按引用传参」，`*` 是通配符 |
| `char s[] = "test";` | `char s[5] = "test";`（含 `\0`） |
| `"test"[i]` | 先赋给 `char[]` 变量再索引 |
| `for (i=0,j=0; ...)` | 一个计数器，只允许一个变量 |

### 3. 参数传递

- 标量默认**值传递**，要引用加 `&`：`void f(int &x)`。
- 数组、结构体、关联数组、报文、信号、诊断对象、定时器 → **自动引用传递**。
- 数组形参**只能写空括号** `int a[]`，写死长度编译报错。

### 4. 保留字

`message`、`key`、`timer`、`msTimer`、`signal`、`sysvar`、`pi`、`testcase`、`testfunction`、`hex`、`raw`、内置类型名 —— **都不能作变量/函数名**，否则报 `Error 1002 parse error`（并常连带给出一堆「符号未知」的假错误）。

### 5. 事件标识符

- 报文：`on message <字面量ID | 数据库报文名 | *>`。**不能用 `message` 变量名当事件。**
- 定时器：`on timer <变量名>` / `on msTimer <变量名>`。
- 以太网：`on ethernetPacket <名>;`（驼峰，一个词，无空格）。
- 其它驼峰：`on ethernetErrorPacket`、`on ethernetStatus`、`on someipMessage`、`on sysvar_update`。
- **禁止**臆造 `on ethernet packet`、`on ethernet_packet`、带连字符的写法。
- **事件处理程序内不能声明数组**（帧缓冲等一律放 `variables {}` 全局）。

### 6. 字符串

- `char[]` 大小要含结尾 `\0`。
- 用 `strncpy` / `snprintf` 时注意长度边界；偏移形式用 `_off` 版本更省事。
- 不要假设有 C 的全部字符串函数，CAPL 用自己的库。

## 四、函数抽象与参数管理

### 1. 什么时候封函数

- 一段动作在 ≥2 处出现（哪怕现在只有 1 处，但属于「机制」），就该下沉到函数层。
- 典型可封装动作：「设信号 → 等待 → 读 ECU 变量 → 判定 → 恢复 → 清 DTC」。

```capl
/* 语义清晰、参数自解释 */
_SignalCheck(signal *sig, int cycle, float value,
             double factor, float offset, sysvarFloat *ecuVar)
{
    Req14();
    setSignal(sig, value);
    testWaitForTimeout(cycle * 10);          /* 设置后必须等待 */
    _readXCP(ecuVar, (float)(long)((value - offset) / factor + 0.5));
    _testnullDTC(0, 1, 0);
    testResetSignalValue(sig);
    testWaitForTimeout(5000);
}
```

### 2. 参数 vs 全局状态

| 放参数（每条用例不同、影响本次动作） | 放全局 `variables {}`（跨调用要记住的环境） |
|---|---|
| 信号对象、ECU 变量引用、周期、缩放因子、偏移、目标值 | 当前是否已连接、当前采集的哪个变量、采集是否在跑、符号表 |

**判据**：本次不同 → 参数；跨调用要记住 → 全局。**不要**为了绕开「声明必须在块首」把函数局部变量提升为全局，那会改变生命周期与作用域。

### 3. 参数校验

- 函数入口对来自用例的参数（人名写的）做防御性判断：符号名找不到、周期 ≤ 0、因子为 0 → **显式判失败**。
- 输出可读信息用 `write(...)` / `writeEx(...)`；判定用 `testStepFail(...)` / `testStepWarning(...)`；必要时 `return` 提前退出。
- **禁止**只 `write` 一句然后继续跑 → 后面读到脏值却报「假通过」。

### 4. 重载

- 同一函数名按参数类型/个数区分，如 `sysvarFloat*` / `sysvarint*` / `sysvarLongLong*` 各写一份。
- 注意：**每份都要独立写全**，CAPL 不会自动类型转换；个数相同仅类型不同时，传错类型容易匹配错版本；重载多了要保证各份逻辑一致（改一处别忘其他份）。

### 5. 没有「参数默认值」怎么办

三种办法，任选其一并全工程统一：
1. **重载**：写参数少的版本，内部补默认值去调完整版。
2. **哨兵值约定**：用特殊值（如 `0` / `-1`）表示「没传、用默认」，函数内判断替换。
3. **拆两个函数**：简单版（内置默认）+ 完整版。

## 五、用例组织与调用

- `testcase`：一个测试用例，报告里对应一条测试项，是报告基本单位。
- `testfunction`：可复用子步骤，不作为独立用例出现在报告顶层，常被 `testcase` 调用。
- 报告步骤：由 `TestStep` / `testStepPass` / `testStepFail` / `testStepWarning` 产生，调用即多一条带判定的步骤。
- **共用前后步骤**：
  - 每条抄一遍 → 重复、易漏、难维护（不推荐）。
  - 抽成公共函数由用例显式调用（推荐）：`Req14()` 开头、`testResetSignalValue()` 结尾。
  - 固定位置统一做（`on start` / Init、公共收尾）：粒度粗，不总能恰到好处复位。
- **状态污染防护**（CAPL 无构造函数/析构函数）：
  - 每条用例**收尾复位**：恢复信号、断开发送/连接、关采集、清 DTC。
  - 每条用例**开头防御性重置**：不假设环境干净。
  - 复位封装成公共收尾函数，统一调用，减少漏掉。

### 故障类型统一入口（新增故障只改一处）

```capl
/* 故障类型：1=报文停发  2=CRC 故障  3=Counter 故障 */
_InjectFault(int faultType, char targetName[])
{
    if (faultType == 1)      { testDisableMsg(报文); }            /* 停发 */
    else if (faultType == 2) { putValue(EV_CRC_xxx, 2); }          /* CRC 注入 */
    else if (faultType == 3) { putValue(EV_Counter_xxx, 1); }      /* Counter 注入 */
    testWaitForTimeout(500);                                       /* 设置后统一等待 */
}
```

用例侧始终一行：`_InjectFault(2, "CRC_xxx");` —— 以后新增故障类型只动 `_InjectFault`，上层用例零改动。

## 六、常见故障注入约定（本工程）

| 用例描述 | CAPL 实现 |
|---|---|
| 报文超时 / 丢失 | `testDisableMsg(报文)` 停发；恢复接口按项目封装 |
| CRC / 校验 / Checksum 信号 | `putValue(EV_{信号名}, 2)` 注入，`putValue(EV_{信号名}, 1)` 恢复 |
| Counter / 计数信号 | `putValue(EV_{信号名}, 1)` 注入，`putValue(EV_{信号名}, 0)` 恢复 |
| 传感器扭矩故障 | 当前操作周期内**不可恢复**；需走一次正常上下电 `Ready_OFF → IGOFF → IGON → Ready_ON` |
| 传感器角度故障 | 当前操作周期内**可恢复**，无需上下电 |

**通用**：设置信号后**必须**跟等待，不要连续无间隔地设置。

## 七、编码问题排查速查（症状 → 原因 → 处理）

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| `Error 1002 parse error` 并连带着一堆「符号未知」 | 用了保留字（`raw`/`hex`/`message` 等）做参数或变量名；或变量声明写在了语句之后 | 改名；把声明移到块首 |
| `Error 1156 unknown function "nsccp_*"` + `Warning 2102` | `ns_ccp.dll` 架构与 CAPL 目标不一致（CANoe 12 的 CAPL 目标是 32 位，必须投 x86 版 DLL） | 换对应架构的 DLL，与 CAPL 文件同目录 |
| 读到的值不刷新 / 一直是旧值 | 设完信号没等下一次发送周期就读；或采集（DAQ）没启动 | 设置后加等待；确认采集在跑 |
| 值第一次对、后面越跑越大 | 局部变量默认 static，跨调用累加 | 用 `stack`，或在函数开头显式赋 0 |
| 断言永远等不到、必然失败 | 期望值未按整数原始值四舍五入（如 `10/0.05625=177.78`，ECU 存 178），而 `testWaitForSignalMatch` 是**精确相等** | 期望值也四舍五入到整数再比 |
| 用例通过但结果不可信 | 参数非法只 `write` 没判失败，后面读到脏值 | 非法参数一律 `testStepFail` 并 `return` |
| 下一条用例莫名失败 | 上一条残留（信号未复位、连接未断、采集未关） | 收尾复位 + 开头防御性重置 |
| 断电/点火循环后读值为空或旧值 | K30 断电或 ECU 复位后，本地连接/采集状态还停在「已连接、正在采集」 | 单独做一次「状态失效」（只清标志，**不发** STOP/DISCONNECT，避免白等超时） |
| 生成代码报「带长度 + 花括号初始化的 const 数组」错 | CAPL 不接受 `const` 修饰带长度数组 | 去掉 `const` |
| 事件处理程序里声明数组报错 | 事件处理程序内不允许声明数组 | 缓冲数组放 `variables {}` 全局 |
| 定时器/事件名字对不上 | 事件标识符写法不合法（空格、下划线、连字符、用变量名当报文事件） | 按「事件标识符」章节的标准写法改 |

## 八、注意事项清单（提交前自检）

- [ ] 用例层没有硬编码 ID / 裸 `output()` / 魔法等待值 / DLL 命令。
- [ ] 每条用例收尾复位、开头防御性重置。
- [ ] 所有「设置」后都跟了等待。
- [ ] 局部变量若需每次清零，已用 `stack` 或显式赋值。
- [ ] 变量声明在块首；`for` 头里没有声明。
- [ ] 数组形参是空括号；`char[]` 带长度含 `\0`。
- [ ] 没使用保留字做名字。
- [ ] 事件写法符合标准（`on message <字面量/库名/*>`、`on ethernetPacket` 驼峰等）。
- [ ] 事件处理程序内没有声明数组。
- [ ] 参数非法时 `testStepFail` 可见失败，不静默通过。
- [ ] 重载各版本逻辑一致、写法齐全。
- [ ] 文件头编码指令保留、未被改动。
- [ ] DLL 与 CAPL 目标架构一致。
- [ ] 判定归一：DTC / sysvar / 信号三类断言走统一函数，失败附带实测值。
