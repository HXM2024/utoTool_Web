# 批量改接连线：选中多条连线后点击接线口批量改接

## Summary

在工况画布上支持**批量改接**：先用框选 / Ctrl+点击选中 ≥2 条连线，然后**直接点击**目标接线口——

- 点**输入口**（`port-in`，绿，左）→ 把选中连线的**入端**（`to`）改到该口；
- 点**输出口**（`port-out`，蓝，右）→ 把选中连线的**出端**（`from`）改到该口。

逐条用现有 `edgeDirOk` 校验方向，不合法的跳过并汇总提示；成功后一次 `emitChange()`（可 Ctrl+Z 整体撤销）+ 一次 `scheduleRecompute()`。用于把一批连错位置的线（典型场景：整排结果线都挂在主序列的错误步骤上）**一次性挪到正确的接线口**。

改动集中在 1 个文件：`frontend/src/components/graph/CaseFrameCanvas.vue`。

## Proposed Changes

### 改动 1：新增 `repointSelectedEdges(frameId, key, side): boolean`

位置：紧接 `batchConnect`（2582–2604）之后，作为它的兄弟函数，保持相同的结构（读状态 → 逐条校验 → 单次回写 → 汇总提示）。

```ts
/** 批量改接：把「当前工况里选中的连线」的对应端改到点中的这个接线口。
 *  点输入口 → 改各连线的 to；点输出口 → 改各连线的 from（与 batchConnect 的约定同源）。
 *  逐条 edgeDirOk 校验，不合法的跳过；最后只 emitChange / scheduleRecompute 各一次。 */
function repointSelectedEdges(frameId: string, key: string, side: 'in' | 'out'): boolean {
  const f = frames.value.find((x) => x.id === frameId)
  if (!f) return false
  // 只认当前工况里确实存在的选中连线（selectedEdgeIds 可能残留别的工况的 id）
  const ids = selectedEdgeIds.value.filter((eid) => !!f.edges[eid])
  if (ids.length < 2) return false

  const end: 'from' | 'to' = side === 'in' ? 'to' : 'from'
  // 撞车判定：同工况内「未选中的边」+「本批已改成功的边」
  const taken = new Set(
    Object.values(f.edges)
      .filter((e) => !ids.includes(e.id))
      .map((e) => `${e.from}->${e.to}`),
  )

  let ok = 0
  let badDir = 0
  let same = 0
  let dup = 0
  for (const eid of ids) {
    const e = f.edges[eid]
    const fromKey = end === 'from' ? key : e.from
    const toKey = end === 'to' ? key : e.to
    if (fromKey === e.from && toKey === e.to) { same++; continue }
    if (!edgeDirOk(fromKey, toKey)) { badDir++; continue }
    const pair = `${fromKey}->${toKey}`
    if (taken.has(pair)) { dup++; continue }
    taken.add(pair)
    e.from = fromKey
    e.to = toKey
    ok++
  }

  if (ok) {
    emitChange()          // 一次快照 + 一次整图回写（Ctrl+Z 可整体撤销）
    scheduleRecompute()   // 一次重算（rAF 合并）
  }
  const skip = badDir + same + dup
  const detail = `方向不合法 ${badDir}、无需改动 ${same}、重复 ${dup}`
  if (ok && !skip) ElMessage.success(`已改接 ${ok} 条连线`)
  else if (ok) ElMessage.success(`已改接 ${ok} 条连线，跳过 ${skip} 条（${detail}）`)
  else if (skip) ElMessage.warning(`未改接任何连线（${detail}）`)
  else ElMessage.warning('连线方向不合法（仅支持：卡片→卡片、卡片→主序列、主序列→卡片）')
  return true           // 选中 ≥2 条即接管这次点击
}
```

关键决策（均已定，落地无需再选）：

- **端别**：`side === 'in' ? 'to' : 'from'`（用户已确认；与 `batchConnect` 的 `side === 'in' ? (nodeKey→key) : (key→nodeKey)` 同源）。
- **范围**：只处理**当前展示工况**内、`f.edges[eid]` 确实存在的选中连线；跨工况残留 id 忽略（与 `deleteSelection`（1101）和 `selectInRect` 一致）。
- **阈值**：选中连线 `< 2` 条 → 返回 `false`，不接管（对齐 `batchConnect` 的 `nids.length < 2 → false`）。
- **只改 `from`/`to`**：`seq` / `pair` 原样保留；用例号由既有 `resolveFrameNumbers` 重新解析，本功能不碰。
- **重复判定**：改接后与同工况内其它连线的 `from->to` 完全相同则跳过（含本批已改成功的），避免同一端口对越改越多；不比较 `seq`/`pair`（与画布「同端口对只画一个徽标」的观感一致，见 2263–2265）。
- **失败反馈**：三类原因分别计数、一次性汇总，不逐条弹窗。
- **选中态保留**：成功后不清空 `selectedEdgeIds`，便于连续改接到下一个口。

### 改动 2：在 `onPortClick` 里接入裸点击（2674–2680）

现状：

```ts
function onPortClick(frameId: string, key: string, side: 'in' | 'out', e: MouseEvent) {
  if (!e.ctrlKey && !e.metaKey) return
  // 已多选卡片（≥2）时：Ctrl 点接线口 = 批量连线，不再走「记住起点 → 再点终点」两步流程
  if (batchConnect(frameId, key, side)) return
  if (side === 'out') onPortOutClick(frameId, key)
  else onPortInClick(frameId, key)
}
```

改为：

```ts
function onPortClick(frameId: string, key: string, side: 'in' | 'out', e: MouseEvent) {
  // 裸点击：已多选连线（≥2）→ 批量改接到这个口；否则维持现状（什么都不做）
  if (!e.ctrlKey && !e.metaKey && !e.shiftKey && !e.altKey) {
    repointSelectedEdges(frameId, key, side)
    return
  }
  // 已多选卡片（≥2）时：Ctrl 点接线口 = 批量连线，不再走「记住起点 → 再点终点」两步流程
  if (batchConnect(frameId, key, side)) return
  if (side === 'out') onPortOutClick(frameId, key)
  else onPortInClick(frameId, key)
}
```

保证：裸点击 + 未多选连线 = 现状不变；Ctrl/Meta 点击 = 现状不变（批量连线 / 两步连线）；两条批量路径靠修饰键天然隔离，不会互相抢。

## Assumptions & Decisions

1. 触发为**裸点击**接线口，阈值**选中连线 ≥2 条**（用户已确认）。
2. 改接的端别**由点击的口方向决定**（用户已确认）。
3. 端口 key 统一走 `isCardKey` / `cardKeyNodeId` / `parseSeqPortKey` / `seqPortKey`——本功能**不新增 key 解析**，只做整串替换（`from`/`to` 直接赋新 key），因此天然兼容旧键 `inj:`/`rec:`/`res:` 与旧序列键 `seq:<seqId>:<idx>`。
4. 批量操作**只回写一次**（`emitChange`）**只重算一次**（`scheduleRecompute`），保证一次 Ctrl+Z 可整体撤销。
5. 端口点击是「点」而非「拖」：拖拽端口建线（`onPortOutDown`/`onLinkUp`）路径完全不变。

## Verification

1. **类型检查**：`cd frontend && .\node_modules\.bin\vue-tsc.cmd --noEmit` → `TSC_EXIT=0`。
2. **实机**（vite 5173 已在跑 + 加载 A47B + 进「图形配置」）：
   - 框选工况 3「No Active->No Active」里同一端接错的若干条连线 → 提示条数与框选一致；
   - 点**输入口** → 这些连线的入端改到该口；再点**输出口**（换一批选中）→ 出端改到该口；
   - 提示数字与「跳过」明细正确；**Ctrl+Z 一次回到改接前**；
   - 反例 1：把（卡片→卡片）的线改到「主序列→主序列」方向 → 全部跳过并提示「方向不合法」；
   - 反例 2：重复点同一个口 → 提示「无需改动」；
   - 边界：只选中 1 条连线时点接线口 → 无任何变化；未选中连线时点接线口 → 无任何变化（现状保持）。
3. **回归**：Ctrl+点端口（批量连线 / 两步连线）、端口拖拽建线、双击连线删除、Delete 删除选中连线均正常。
