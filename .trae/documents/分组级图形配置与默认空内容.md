# 图形化配置按分组隔离 + 新建默认空 + 分组可收起

## 一、概述（Summary）

Function 模块的「图形化配置」当前把**卡片库（故障注入/序列/检查）**、**对象映射表**、**值资源库**放在**配置级/全局级共享**，只有工况框 `frames` 是分组级。这导致：

1. 新建配置/新建分组后，打开图形编辑器会自动出现一堆默认卡片与映射（来自全局库），与"默认空"的预期不符。
2. 不同分组无法拥有各自的对象映射表与卡片库，无法表达"不同分组不同内容"。

本方案将 **卡片库 / 对象映射表 / 值资源库下沉到分组级**，新建分组时三者**默认为空**；全局库（`Function_global_library.json`）保留为**模板**，改为**手动导入/导出**；并在 FunctionView 预览页让**每个分组卡片可收起**。

### 已存在的隐式缺陷（顺带修复）

1. `FunctionView` 模板 `v-model:cards="cards"` 是**无效绑定**——`FunctionGraphEditor` 无 `cards` prop / `update:cards` 事件（[FunctionView.vue#L239-L248](file:///e:/Python/AutoTool_Web/frontend/src/views/FunctionView.vue#L239-L248) vs [FunctionGraphEditor.vue#L106-L118](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/FunctionGraphEditor.vue#L106-L118)），故配置里的 `cards` 永远不随编辑更新。本方案改为分组级后该绑定移除。
2. `doGlobalSave` 会把**当前编辑内容自动写回全局库**，多分组场景下会互相覆盖。

## 三、目标与决策（Assumptions & Decisions）

依据澄清结论锁定：

| 决策项 | 结论 |
|---|---|
| 卡片库（故障注入/序列/检查） | **按分组隔离** |
| 对象映射表 `mapping` | **按分组隔离** |
| 值资源库 `valueLibrary` | **按分组隔离** |
| 新建分组时的初始内容 | **完全空白**（三者为空，不是从全局库复制） |
| 函数库 / 对象浏览器 | **保持全局**，不隔离 |
| 全局库角色 | 保留作**模板**；编辑器**不再自动注入、不再自动写回**；提供**手动「从全局库导入 / 导出为全局库」** |
| 用例分组可收起 | 指 **FunctionView 预览页的每个分组卡片**可折叠（编辑器顶部标签栏不改） |

### 数据归属（改造后）

```
配置
 └─ graph
     └─ groups: CaseGroup[]            ← 分组级
          ├─ name / naming
          ├─ frames: CaseFrame[]        ← 工况（原有）
          ├─ cases?: ImportedCase[]      ← Excel 导入用例（原有）
          ├─ cards?: CardLibrary         ← 新增：分组卡片库
          ├─ mapping?: ObjectMapping     ← 新增：分组对象映射表
          └─ valueLibrary?: ValueResource[]  ← 新增：分组值资源库
```

顶层 `mapping` / `cards` / `value_library` **保留为配置级兜底**（旧配置兼容），后端优先取分组级。

## 四、变更方案（Proposed Changes）

### 4.1 类型层 — `frontend/src/types/functionGraph.ts`

**做什么**：`CaseGroup` 增加三个可选字段；新增分组工厂与空值常量。

**怎么做**：
```ts
export interface CaseGroup {
  id: string
  name: string
  frames: CaseFrame[]
  naming?: 'default' | 'path'
  cases?: ImportedCase[]
  // 新增：分组级内容（新建分组默认空）
  cards?: CardLibrary
  mapping?: ObjectMapping
  valueLibrary?: ValueResource[]
}

/** 空值常量（复用于计算属性默认返回，避免每次新建对象导致响应式抖动） */
export const EMPTY_CARDS: CardLibrary = { inject: [], sequence: [], result: [] }
export const EMPTY_MAPPING: ObjectMapping = { signals: [], dtcs: [], messages: [], envvars: [], a2l: [] }
export const EMPTY_VALUES: ValueResource[] = []

/** 新建分组：内容完全空白 */
export function emptyCaseGroup(name: string): CaseGroup {
  return {
    id: genId('group'),
    name,
    frames: [],
    cards: { inject: [], sequence: [], result: [] },
    mapping: { signals: [], dtcs: [], messages: [], envvars: [], a2l: [] },
    valueLibrary: [],
  }
}
```
同时让 `emptyGraph()` 的默认分组也使用 `emptyCaseGroup` 语义（保持字段齐全）。

**为什么**：字段必须**存在且为空**（而非 `undefined`），后端才会判定"该分组有自己的内容"从而不回落全局库。

### 4.2 编辑器 — `frontend/src/components/graph/FunctionGraphEditor.vue`

**做什么**：把 `cardLibrary` / `mapping` / `valueLibrary` 从"编辑器独立 ref"改为**读写活动分组**；新建分组默认空；移除自动注入/自动写回全局库；新增手动导入/导出全局模板。

**怎么做**：

1. **活动分组内容改为计算属性（读写都落到 `activeGroup`）**
```ts
const activeGroup = computed<CaseGroup | null>(
  () => (graph.value.groups || []).find((g) => g.id === activeGroupId.value) || null,
)
const cardLibrary = computed<CardLibrary>({
  get: () => activeGroup.value?.cards ?? EMPTY_CARDS,
  set: (v) => { if (activeGroup.value) activeGroup.value.cards = v },
})
const mapping = computed<ObjectMapping>({
  get: () => activeGroup.value?.mapping ?? EMPTY_MAPPING,
  set: (v) => { if (activeGroup.value) activeGroup.value.mapping = v },
})
const valueLibrary = computed<ValueResource[]>({
  get: () => activeGroup.value?.valueLibrary ?? EMPTY_VALUES,
  set: (v) => { if (activeGroup.value) activeGroup.value.valueLibrary = v },
})
```
> 注意：多处代码对其**原地增删**（如 `cardLibrary.value.inject.push(...)`），计算属性 get 返回分组内对象引用，原地改可保持响应式；整体赋值走 set。`provide('geCtx', …)` 继续提供这三个 computed（`PanelBody` 的 `ctx.xxx.value` 用法不变）。

2. **`ensureGroups()` 迁移与补齐**（兼容旧配置）
   - 每个分组缺失 `cards/mapping/valueLibrary` 时补齐字段：
     - `mapping`：优先用**分组已有**；否则用**配置级 `props.mapping`**（迁移旧数据，避免丢失）；仍为空则空对象。
     - `cards`：优先用分组已有；否则用配置级 `props.cards`（若为空则保持空 → 符合"默认空"）。
     - `valueLibrary`：同上，配置级来源为 `props.valueLibrary`（新增 props，见下）。
   - `g.frames = active.frames` 镜像逻辑不变。

3. **新增 props/emits**（为迁移与回写）
   - props 增加 `cards?: CardLibrary`、`valueLibrary?: ValueResource[]`（仅用于**旧配置迁移兜底**）。
   - emits 增加 `update:cards`、`update:valueLibrary`（可选，便于父级同步；主回写仍走 `update:graph`）。

4. **`addGroup()` 改为空白分组**
```ts
const grp = emptyCaseGroup(`GraphCase${g.groups.length + 1}`)
```
   （`frames/cards/mapping/valueLibrary` 全空）

5. **`switchGroup()` 保持整体切换语义**：切 `activeGroupId` → `graph.frames = grp.frames`；计算属性自动指向新分组的 cards/mapping/valueLibrary，无需手动搬运。

6. **移除全局库自动注入/写回**
   - `loadGlobal()`：**保留**加载 `globalLibrary`（作为模板数据源，存入 `globalTemplate` ref），但**不再**覆盖 `cardLibrary` / `mapping` / `valueLibrary`，也**不再** `emit('update:mapping')`。
   - 删除 `doGlobalSave()` / `scheduleGlobalSave()` 的自动调用点（`onMappingChange`/`onAddMapping`/`onValueLibraryChange`/`createCard`/`saveCard`/`duplicateCard*`/`removeCard*`/`pasteEntity` 中的 `scheduleGlobalSave()` 全部移除），改为**只回写当前分组并 `emit('update:graph')`**。
   - 新增 `emitGroupUpdate()`：`syncActiveGroupFrames()` + `emit('update:graph', 深拷贝)`，作为分组内容变更的统一回写出口。

7. **新增手动模板导入/导出**（在编辑器顶部 `.ge-groups` 栏右侧新增两个小按钮 `导入全局模板` / `导出为全局模板`）
   - 「导入全局模板」：把 `globalTemplate` 的 `cards/mapping/value_library` **深拷贝**写入活动分组（覆盖式，`ElMessageBox.confirm` 二次确认）。
   - 「导出为全局模板」：把活动分组的 `cards/mapping/valueLibrary` 通过既有 `saveGlobalLibrary(...)` 写回全局库（`ElMessageBox.confirm` 二次确认）。
   - 复用既有 API `getGlobalLibrary` / `saveGlobalLibrary`（[function.ts](file:///e:/Python/AutoTool_Web/frontend/src/api/function.ts#L42-L48)），无需新增后端接口。
   - 为支持「导入」需保留一个 `globalTemplate` ref：`loadGlobal()` 把全局库读入 `globalTemplate`（不再写入当前分组）。

8. **`onAddMapping` / `mergeMappingEntries` / `collectCardVariables`**：逻辑保留，但写入目标改为活动分组的 `mapping`，并改调 `emitGroupUpdate()`（不再写全局库）。

**做什么**：`expand_cases` 分组分支改为**逐分组构建 lookup**（分组级优先，回落配置级）。

**怎么做**（改造 [expand_cases](file:///e:/Python/AutoTool_Web/backend/services/function_graph.py#L1315-L1374) 分组循环体）：
```python
for gi, g in enumerate(groups):
    ...
    gname = ...
    gnaming = ...
    # 分组级内容优先；缺失回落配置级（旧配置兼容）
    gmapping = g.get("mapping") if isinstance(g.get("mapping"), dict) else mapping
    gcards = g.get("cards") if isinstance(g.get("cards"), dict) else cards
    gvalues = g.get("value_library") if isinstance(g.get("value_library"), list) else values
    glookup = build_mapping_lookup(gmapping)
    gcard_lookup = build_card_lookup(gcards)

    if gframes:
        gcases = _expand_by_frames({"frames": gframes}, glookup, gnaming, gcard_lookup, gvalue_lookup, prefix=gname)
    elif gedges:
        gcases = _expand_by_edges(gnodes, gedges, glookup, gnaming, gcard_lookup, gvalue_lookup, prefix=gname)
    elif gnodes:
        gcases = _expand_cartesian(gnodes, glookup, gnaming, gcard_lookup, gvalue_lookup, prefix=gname)

```
> 顶层 `lookup`/`card_lookup`/`value_lookup`（L1311-1313）仍保留，供**无分组**分支与配置级兜底使用。字段 key 统一用前端写入的 `valueLibrary` 还是 `value_library`？—— 统一在**后端读 `value_library`、前端写 `valueLibrary`** 会不一致，故**统一采用 `valueLibrary`**（分组内字段名与前端一致），后端读 `g.get("valueLibrary")`。同理 `cards`/`mapping` 命名已一致，无需转换。

## 五、数据迁移与兼容（Migration & Compatibility）

| 场景 | 处理 |
|---|---|
| 旧配置（分组无 `cards/mapping/valueLibrary`） | 打开编辑器时 `ensureGroups` / `normalizeGraph` 用**配置级** `mapping`/`cards`/`value_library` 迁移进分组（保留用户已有数据）；配置级为空则分组为空 |
| 旧配置单分组 | 迁移到唯一分组，行为不变 |
| 旧配置多分组 | 配置级内容**复制**到每个缺失该字段的分组（与旧"全局共享"语义等价） |
| 新增分组 | 三者为空（不复制） |
| 保存 | 内容写入 `graph.groups[].*`；配置级 `mapping`/`cards` 继续写（兜底） |
| 后端 | 分组级优先、配置级兜底；无分组时走配置级 |

**兼容性**：`expand_cases` 的签名与顶层参数不变，仅内部读取更细；`build_testcase_can` / `build_test_case_list` 签名不变。
