# 连线编号填写优化 —— 「编号选择器」方案

## 一、Summary

把「双击序号徽标 → 裸输入框手敲编号」升级为「**双击序号徽标 → 弹出编号选择器**」：
候选编号 = **当前工况实际在用的编号**（点一下就选/再点取消），支持**快捷键多选（Ctrl 切换 / Shift 区间连选）与拖拽框选**，**清空 = 全部**（等价于现在的空显式编号 / 继承语义）；
同时给手填输入框补上**范围与步进简写**（`1-30`、`1,3,5-9`、`2-20/2`）。

纯前端 UX 改动：**不动数据模型（`seq`** **/** **`pair`）、不动** **`resolveFrameNumbers`、不动后端** —— 编号解析结果与用例展开数量、用例名完全不变。

### 2.2 当前为何繁琐（用户诉求的直接原因）

1. **只能逐条、盲敲**：唯一入口是双击徽标；编号多的线要手打一长串数字（`1,2,3…30`），无范围简写。
2. **看不到候选**：不知道本工况到底存在哪些编号，只能凭记忆敲，敲错号就多出/漏掉用例。
3. **没有「点选」**：要复用「已有的编号」，目前只能重新手打一遍。

### 2.3 关键约束（决定实现方式）

* `.cfc-canvas` 是 `overflow: auto`（[第 3364-3370 行](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L3364-L3370)），`.edge-label` 是 `position: absolute`（第 3537-3541 行）→ **面板若就地绝对定位会被滚动容器裁剪**，必须用 teleport 的浮层。

* 画布已经在用 `el-popover`（工具栏帮助浮层，[第 7-21 行](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L7-L21)），Element Plus 的 popover 默认 teleport 到 body → **直接复用该模式**。

## 三、Proposed Changes

### 改动 1：`parseEdgeNums` 支持范围 / 步进（纯函数）

文件：[CaseFrameCanvas.vue](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L3018-L3026) 第 3018-3026 行

* `a-b` → `a..b`（`a>b` 自动翻转，如 `8-3` = 3…8）

* `a-b/s` → 从 a 开始、步进 s（`s` 非法或 ≤0 时按 1 处理），如 `2-20/2` = 2,4,…,20

* 仍支持 `,` / `，` / 空白分隔；整体去重、升序

* 非法片段（`abc`、`0`、负数）忽略；**单个片段展开后总数上限 500**（超出则截断，由调用处提示），避免 `1-999999` 把数组撑爆

* 保持「空串 → `[]`」语义（= 全部）

> 只在 `parseEdgeNums` 内部实现，签名与返回类型不变，所有既有调用点（`saveEdgeInline`）零改动。

### 改动 2：把「编辑态」从裸 input 改为 `el-popover` 选择器

文件：[CaseFrameCanvas.vue](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L109-L137) 第 109-137 行（模板）+ [editEdge](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L3031-L3040) / [saveEdgeInline](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L3041-L3058) / [cancelEdgeEdit](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L3059-L3063) 第 3031-3063 行

**模板**：徽标**常驻**并作为 popover 的 reference（不再被 input 顶掉，编辑时也能看见自己在改哪条线）：

```
<el-popover
  :visible="editingEdgeId === p.edgeId"
  placement="bottom-start"
  :width="260"
  popper-class="cfc-num-pop"
  :teleported="true"
>
  <template #reference>
    <span class="label-badge" :class="{ 'badge-selected': ..., 'badge-editing': editingEdgeId === p.edgeId }"
          @dblclick.stop="editEdge(f.id, p.edgeId)" …>{{ p.label }}</span>
  </template>
  <!-- 选择器内容，见下 -->
</el-popover>
```

**.edge-input 移到 popover 内部**（手填行），保持 `v-model="editingEdgeValue"`、`:style="{ width: edgeInputWidth }"`、Enter=确定 / Esc=取消；**去掉** **`@blur`** **提交**（原因见下面第 10 条）。

**popover 内容（编号选择器）**：

1. **标题行**：`编号` + 该连线类型（`注入线` / `结果线` / `链式线`，用既有 `edgeKind(e)` 判定）
2. **当前状态只读提示**：`当前：1,2,3`（有显式编号）或 `当前：全部（继承自左侧）`（显式为空）——直接展示 `edgePathCache` 里 `p.nums` 的生效值，解决「徽标显示有效值、双击进去却是空的」的困惑，但**只读、不写回**
3. **候选编号 chips**：数据源 = **当前工况实际在用的编号**（`caseNums`）∪ 该连线显式编号里超出 `caseNums` 的号，升序去重。已选中的 chip 高亮（`.active`）。chips 是原生 `<button type="button">`（天然可 Tab 聚焦、空格/回车切换）
4. **单选 + 快捷键多选**（手势语言与画布连线对齐，见 [toggleEdgeSel](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L2779-L2791) 第 2779-2791 行）：

   * **普通单击** → 只选它（清掉其它），并把它记为「锚点」

   * **Ctrl / Cmd + 单击** → 切换该 chip 选中态（追加 / 取消），锚点更新为它

   * **Shift + 单击** → 从「锚点」到该 chip 的**区间整段选中**（不取消，锚点不变），区间按 chips 的升序下标计算

   * 没有锚点时，Shift 单击按普通单击处理
5. **拖拽框选**：在 chips 容器 `.num-grid` 上按住左键拖动 ≥ `MARQUEE_MIN`(4px) → 出虚线框；松手后**框到的 chip 全部选中（替换式，与画布框选一致）**；若拖动时按住 `Ctrl`，则**并入**现有选中。实现完全复用画布框选的既有模式（[onCanvasMouseDown](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L2854-L2874) / [onMarqueeMove](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L2899-L2904) / [onMarqueeUp](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L2905-L2919)）：

   * `mousedown` 记录起点 → `window` 上挂 `mousemove` / `mouseup`

   * **命中判定用视口坐标**（框矩形与各 chip 的 `getBoundingClientRect()` 求交），避免容器滚动造成错位

   * 框的**显示**用 `position: absolute` 挂在 `.num-grid` 内：`left = 视口x1 − gridRect.left + grid.scrollLeft`（同理 top），故 `.num-grid` 需 `position: relative`

   * `.num-grid` 可滚动（chips 多时），拖动期间滚动要按滚动量反向平移起点（同 [onMarqueeScroll](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L2889-L2898)）

   * 框选结束后置 `numMarqueeSuppressClick = true`，搭配 `@click.capture` 吞掉紧随其后的那次 click，否则会再按「普通单击」把选中改回一个
6. **全空提示**：一个都不选时显示 `未选编号 = 全部用例`（与现状的空值语义、徽标「全部」一致）
7. **手填行**：`.edge-input`，`placeholder="如 1,2,5-8"`；输入内容实时解析并同步 chips 选中态（解析为空 → 清空选择）
8. **底部按钮**：`确定`（`saveEdgeInline`）/ `清空`（把 chips 与手填内容一并置空，**不提交**，即「全部」的预备态）/ `取消`（`cancelEdgeEdit`）
9. **单一真源**：chips 选中态**不是**独立状态，而是 `computed(() => new Set(parseEdgeNums(editingEdgeValue.value)))`；点 chip / 框选 / 手填都只改写 `editingEdgeValue` 这一个字符串，**唯一写回路径仍是** **`saveEdgeInline`**。锚点是一个组件级局部变量 `let numAnchorIdx: number | null`（面板打开时置 null）
10. **关闭与提交时机**：**必须移除** `.edge-input` 上的 `@blur="saveEdgeInline"`（只保留 Enter=确定、Esc=取消）。否则点 chip / 拖框选都会让输入框失焦 → 立刻提交并关闭面板，多选手势做不完。原「点别处自动保存」的行为由改动 3 的 `onWindowMouseDown` 承担，**行为不回退**

**数据源**：`caseNums` 目前只在 [recompute()](file:///e:/Python/AutoTool_Web/frontend/src/components/graph/CaseFrameCanvas.vue#L2238-L2241) 第 2241 行 `const { edgeNums } = resolveFrameNumbers(f)` 里被解构丢弃 →

* 改为 `const { edgeNums, caseNums } = resolveFrameNumbers(f)`

* 新增 `const frameCaseNums = ref<Record<string, number[]>>({})`，在同一循环里 `frameCaseNums.value[f.id] = caseNums`（与 `edgePathCache` 同生命周期、同刷新时机）

**候选集为空时**（工况还没任何编号）：面板显示 `本工况还没有编号：先在注入线上填一个，或用下方手填`，chips 区留空但不报错。

## 四、Assumptions & Decisions

| 决策        | 取值                                                                        | 来源                    |
| --------- | ------------------------------------------------------------------------- | --------------------- |
| 候选编号集合    | **只列当前工况实际在用的编号**（`caseNums`）                                             | 你的选择                  |
| 「一键重排编号」  | **不做**（本轮只做选择器）                                                           | 你的选择                  |
| 清空语义      | 清空 = 全部（显式编号为空 → 继承），与现状、与徽标「全部」完全一致                                      | 你的要求                  |

## 五、Verification

1. `cd frontend && npx vue-tsc --noEmit` 通过（TS 无错误）。
2. `parseEdgeNums` 纯函数样例（可在 `node` 里手测或临时脚本）：

   * `"1,2,3"` → `[1,2,3]`；`"1-5"` → `[1,2,3,4,5]`；`"8-3"` → `[3..8]`

   * `""` → `[]`；`"abc,0,-2"` → `[]`；`"1-999999"` → 截断到 500 项（触发提示）
3. 实机点验清单（画布已挂载、工况内有若干编号）：

   * 双击徽标 → 弹出面板，候选 chips = 该工况在用的编号（升序）

   * 普通单击 chip → 只选它；**再点同一个 → 只它被取消**

   * **Ctrl/Cmd + 单击** → 逐个追加 / 取消

   * **Shift + 单击** → 从上次点击的 chip 到本次点击的 chip 之间整段选中（不取消）

   * **在候选区拖拽** → 出虚线框，松手后框到的全选中（替换式）；**Ctrl + 拖拽** → 并入

   * **连续多次点选 / 框选不会中途提交关闭面板**（关键：验证失焦提交已移除）

   * 点面板内按钮 / 空白处 → 面板不关闭、不提交

   * 全部取消 → 徽标回到「全部」，用例数不变（= 对所有用例生效）

   * 手填 `1-5` → 上方 chips 1..5 全部变选中

   * 回车 = 确定、Esc = 取消；点画布其它地方 = 提交（与现状一致）

   * 提交后 Ctrl+Z 可整条撤销；用例预览里的编号与画布一致
4. 回归：`.edge-input` 宽度自适应、`.label-badge` 单击高亮 / Ctrl 多选 / `badgeOnSelect` 去重逻辑均不变；画布自身的框选 / 快捷键（Delete、Ctrl+Z）不受面板内框选影响；编号解析（`resolveFrameNumbers`）与后端用例展开结果不变。
