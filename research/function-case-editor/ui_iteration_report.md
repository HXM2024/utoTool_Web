# 功能用例配置 · UI 迭代报告

## 2026-09-08 22:00 第 1 轮

### 分析与结论
聚焦用户偏好「简洁、紧凑、一目了然、易上手」，本轮选取编辑器（StepEditor）顶部信息区的两个具体问题：

1. **操作分散、认知负担高**：名称输入、类型选择、保存按钮散落在 `.se-form`，而「从代码生成」「添加步骤」两个新增操作又单独放在 `.se-step-head`，用户无法一眼形成「我要编辑这个卡片 → 该点哪里」的心智路径。
2. **视觉噪音**：`.se-step-head` 的标题文案冗长（`步骤编排（拖入函数/对象自动生成 · 拖拽排序 / 复制 / 删除）`），把标题与操作说明混为一体，干扰扫读。

### 具体改动（StepEditor.vue）
- 新增外层 `.se-toolbar` 容器，将「对象编辑」（类型 + 名称 + 保存）与「步骤新增」（代码生成 + 添加步骤）按语义分组为左右两个区域（`.se-form` / `.se-actions`），一条横向工具栏即可承载全部入口。
- 精简标题：标题改为「步骤编排」，冗长说明拆分为独立的 `.se-step-hint` 浅灰提示行，降低扫读噪音。
- 统一控件尺寸为 `size="small"`，与步骤列表行保持一致，视觉更紧凑。
- 「从代码生成」更名为「代码生成」，补 `Document` 图标与 tooltip 说明，减少裸文本歧义。
- 调整样式：`.se-name` 增加 `min-width` 防止挤压；`justify-content: space-between` + `flex-wrap` 保证窄面板下可换行不溢出。

### 功能完整性
未改动任何逻辑与数据模型。名称/类型编辑、保存、代码生成、添加步骤、拖拽填充、展开、排序、复制、删除均保持不变。

### 验证
`npx vue-tsc --noEmit` 通过（exit code 0）。

### 剩余可优化项（后续轮次）
1. 函数/自定义两类的 `el-radio-button` 与函数名输入框并列，函数名输入框占宽过大导致步骤行拥挤，可考虑更紧凑的两态布局。
2. 步骤行操作按钮（上移/下移/复制/删除/展开）数量多、图标混用（`…`/`⧉`），可统一为 Element Plus 图标并收敛到 hover 显隐以降低常态噪音。
3. 左侧面板（工况/卡片列表）与「对象映射表」的拖拽手柄 `⠿` 与提示文案可进一步统一视觉语义。
4. 属性面板（NodeInspector）与 CaseFrameCanvas 的节点操作按钮 hover 显隐存在一致性问题。

## 2026-09-08 23:00 第 2 轮

### 分析与结论
承接上一轮「剩余可优化项」，本轮聚焦 StepEditor 步骤行的两个具体问题：

1. **操作按钮图标混用**：步骤行操作按钮中「展开」用文本符号 `…`、「复制」用 `⧉`，而上移/下移/删除用的是 Element Plus 图标（Top/Bottom/Close），同一行内图标与文本符号混杂，破坏视觉一致性与可扫读性，加大认知负担。
2. **步骤行拥挤**：`.step-fun` 函数名输入框 `flex: 1` 缺少 `min-width: 0`，在窄面板下可能挤压两侧控件；操作按钮间缺少分组区隔，难以快速分辨「内容编辑区」与「行操作区」。

### 具体改动（StepEditor.vue）
- 统一操作按钮图标：删除文本符号 `⧉`/`…`，改为 Element Plus 图标——复制用 `CopyDocument`；展开/收起用 `CaretTop`/`CaretBottom`（随展开状态动态切换），并相应调整 tooltip 文案（「展开源代码/收起源代码」「展开/收起」），语义更清晰。
- 优化步骤行布局：`.step-fun` 增加 `min-width: 0` 防止 flex 子项在窄容器下撑破；`.step-head` 间距由 `gap: 6px` 微调为 `5px`；`.expand-btn` 收紧 `padding: 2px` 并用 `margin-left: 4px` 与前面的函数名输入区形成轻量分组，降低操作区混入内容区的视觉噪音。

### 功能完整性
仅替换图标与微调样式，未改动任何逻辑、事件绑定与数据模型。展开/收起、复制、上移/下移、删除、拖拽填充等行为保持一致。

### 验证
`npx vue-tsc --noEmit` 通过（exit code 0）。过程中曾因未正确引用新图标 `CaretTop/CaretBottom/CopyDocument` 导致类型报错，已确认 `@element-plus/icons-vue@2.3.2` 存在这些导出并完成补充引用后通过。

### 剩余可优化项（后续轮次）
1. 函数/自定义两类的 `el-radio-button` 与函数名输入框并列，函数名输入框占宽过大，可考虑更紧凑的两态布局或收窄函数名输入区。
2. 左侧面板（工况/卡片列表）与「对象映射表」的拖拽手柄 `⠿` 与提示文案可进一步统一视觉语义。
3. 属性面板（NodeInspector）与 CaseFrameCanvas 的节点操作按钮 hover 显隐存在一致性问题。
4. CaseFrameCanvas 顶部工具栏提示文案冗长（`序列=可复用卡片…双击节点编辑`），可精简约简为图标分组 + tooltip，降低扫读噪音。
5. 面板停靠的五向放置区指示器（`.dock-zone`）文字「上/下/左/右/中」可用方向图标替代，进一步提升可读性。

## 2026-09-08 22:00 第 3 轮（本文件第 2 条同名时间戳之上追加，实际为本轮）

> 注：本轮与既有的「22:00 第 1 轮」「23:00 第 2 轮」时间线重叠，为遵循任务「从今晚 22:00 开始每小时一轮」，本轮记为第 3 轮。

### 分析与结论
承接前两轮「剩余可优化项」，本轮借鉴 dSPACE AutomationDesk / VS Code 的成熟范式，聚焦两个低风险、可读性收益明确的问题：

1. **五向放置区指示器可读性差**：`.dock-zone` 用纯文字「上/下/左/右/中」提示停靠方向，字小、色浅、虚线边框在拖拽状态下辨识度低，与「VS Code 五向停靠区」心智模型不符，也无法一眼分辨中心「叠加为页签」与四边「分栏停靠」的语义差异。
2. **步骤行内容区与操作区无区隔**：StepEditor 步骤行中「展开」按钮与「复制/上移/下移/删除」四个操作按钮连续排列，且函数名输入框 `flex: 1` 无上限宽度，在宽面板下被拉伸过长，导致内容区与操作区视觉混杂、行内拥挤。

### 具体改动
**FunctionGraphEditor.vue**
- 五向放置区文字替换为 Element Plus 方向/缩放图标：上=`Top`、下=`Bottom`、左=`Back`、右=`Right`、中=`ScaleToOriginal`，语义与 VS Code 停靠区一致，跨语言可读。
- 指示器样式强化：背景由半透明蓝改为近白 `rgba(255,255,255,0.92)` + 实线浅灰边框 + 轻微投影，hover 激活态保留主色高亮，拖拽时更醒目、层次更清晰。

**StepEditor.vue**
- `.step-fun` 增加 `max-width: 460px`，避免宽面板下函数名输入框过度拉伸；保留 `min-width: 0` 防止窄面板挤压。
- `.step-kind-toggle` 内联收紧 `el-radio-button` 内边距（`padding: 5px 8px`），「函数/自定义」切换更紧凑。
- 在「展开」与「复制/上移/下移/删除」之间新增 `.step-ops-divider` 竖向分隔线，将「内容相关操作」与「行级增删/排序操作」视觉分组。

### 功能完整性
仅替换图标、新增分隔线与非功能性样式（尺寸/间距/颜色），未改动任何事件绑定、拖拽逻辑与数据模型。面板停靠、五向放置、步骤拖拽生成、对象拖入参数、映射表两列、函数/自定义两类步骤、输入框展开等能力均保持不变。

### 验证
`npx vue-tsc --noEmit` 通过（exit code 0）。

### 剩余可优化项（后续轮次）
1. 左侧面板（工况/卡片列表）与「对象映射表」的拖拽手柄 `⠿` 与提示文案可进一步统一视觉语义（目前用点阵字符，跨平台渲染不一致）。
2. CaseFrameCanvas 顶部工具栏提示文案冗长，可精简约简为图标分组 + tooltip，降低扫读噪音。
3. CaseFrameCanvas 节点操作按钮使用 `⧉`/`↑`/`↓`/`✎`/`✕` 等字符符号，与前两轮 StepEditor 已收敛为 Element Plus 图标的做法不一致，可统一。

5. 顶部工具栏（ge-header）动作按钮无 tooltip 说明，可补充 tooltip 提升易上手性。
